# AGENTS.md

Rules for anyone (human or agent) changing this repository. Start with `README.md`, then
`decisions/0001-ledger-api.md`.

## What this is

A multi-tenant German bookkeeping core reached only through an API. Platforms (Digipost,
reserwirt) keep books for their tenants. Every capability is one operation in
`packages/operations`, exposed as `POST /v1/<name>`, in the OpenAPI document and as an MCP tool
under the same name.

## Layout

- `packages/core`: pure bookkeeping logic, no I/O. Moved from Digipost's `src/modules/ledger/core`.
- `packages/db`: Drizzle schema (Postgres schema `ledger`), migrations, SQL triggers, repositories.
- `packages/operations`: the operation catalog. A new capability is a new operation here, never a
  hand-written route.
- `apps/api`: the Hono app (HTTP, OpenAPI, MCP), bundled by `scripts/build.mjs` into a Vercel
  Build Output (region `fra1`).
- `packages/sdk`: the client generated from the OpenAPI document.

## Rules

- **Public repository.** Never commit real tenant data: no real bookings, amounts, names of real
  people, tax advisors or customers, no production ids. Test fixtures use invented data.
- **Tenant scoping.** Every query on a tenant-owned table filters by the tenant resolved from the
  platform key and `Ledger-Tenant`, never by an id from the request body. The tenant is resolved
  in exactly one place (`apps/api/src/caller.ts`).
- **The database refuses bad bookings.** The balance and filing-lock triggers stay; never work
  around them in code.
- **Migrations** are generated by drizzle-kit from `packages/db`'s schema; the trigger SQL is a
  custom migration. Never run a migration or any DDL against a shared or production database
  without the owner's explicit approval in the chat for that specific run. Local and CI tests use
  a throwaway Postgres.
- **Stable error codes** (`snake_case`, `as const` sets) for anything a caller branches on.
- **English** for code, identifiers, comments, docs and commit messages. No em dash and no en dash
  in docs or descriptions.
- **Before a pull request:** `pnpm verify` (typecheck, lint, unit tests), plus `pnpm test:db` when
  the database layer changes. CI runs both; a push to main deploys.
